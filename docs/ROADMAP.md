# 设计原则与下一代方案（Roadmap）

> 本文件记录本项目在设计讨论中形成的**判定纲领、尺子，以及下一代方案的候选清单**。
> 它不是承诺，而是**可追溯的决定**——包括"我们决定不做什么"以及为什么。

---

## 0. 纲领：风险分级原则

> 目标不是消灭所有风险，而是**把风险从"结构性"降为"执行性"**：
> 凡"只要人松懈就会发生"的，必须用机制消除；凡"即使尽责也可能发生"的，保留它——但确保**可检测、可恢复**。
> 且所有结构性兜底，**必须零摩擦**。

**判据**

- **结构性风险** = 迟早会发生（依赖人的松懈、自觉、记忆）
- **执行风险** = 偶尔会发生（即使所有人都尽责）
- **"只要人稍一松懈就会发生" → 它是结构性风险，不是执行风险。**

**推论**：克制 与 "只清结构性风险" 是同一件事。过度设计不是更安全，是把执行风险换成更糟的 **结构复杂度风险**。

---

## 1. 判定尺子（七条）

1. 新增外部依赖 / 跨系统集成？→ 怀疑
2. 新增需长期维护的状态 / 表 / 定时任务？→ 怀疑
3. 只是让已有数据可见？→ 优先
4. 能用**删减**完成？→ 最优先
5. 会不会把一线推回手动忽略？→ 方向错
6. **是否已有归属方**（WAF / 封堵方 / 飞书 / 网关）？→ 有则不接手
7. **能否用已有原语解决**？→ 能，则不新增机制

> 附加：**每个新增都必须回答"它替代了什么"**；答不上来的就是负债。

### B5 · 巡检留痕（未做）

- **要消除的结构性风险**：巡检若只靠制度，"人会不会去巡检"就是确定性的失效。
- **机制**：监控人员**打开内网源视图时自动记录一条巡检事件**（复用既有审计，不新建表、不建巡检系统）。
- **零摩擦铁律**：**打开即记录**，不要"点确认巡检"按钮——任何额外步骤都会被敷衍。
- **节流**：同一人 + 同一视图 + 同一天只记一次。
- **待决**：节流粒度。

### B6 · 研判动作登记（已落地 · 原「沉底门禁」设计已被取代）

**结论：原设计过度了。** 与一线讨论后确认——一条告警只有三个动作，且三者的下游痕迹完全不同，因此**只有「忽略」需要理由**：

| 结论 | 可见性 | 需要理由？ |
|---|---|---|
| **忽略** | 从主视图移出 | ✅ 二级枚举（`非攻击` / `留待观察` / `其他`+说明）——**三个动作里只有它能凭空让告警消失** |
| **排查** | 从主视图移出 + 标记「排查中」，可用「🔎 排查中」视图找回（**不进规则、分数保留**） | ❌ 下游要拉人、沟通、截图，**痕迹比封堵还重** |
| **封堵** | 从主视图移出 | ❌ 下游须与外界沟通并发截图，证据在系统外 |

- **原则**：摩擦只加在"让告警消失"的那一侧，而不是均匀加在所有动作上；能枚举的就别让人写。
- **"移出"不等于"消失"**：三者都从主视图移出，但「排查中」有专属视图可找回——否则就变成了盲区。
- **四个入口统一**（单条 / IP 批量 / 聚合 / 批量），顺带堵掉原先"聚合与批量走 `prompt`、留空自动填默认值"的绕过口。
- **零新增字段**：`排查` 复用原先恒为 `0` 的死字段 `is_processed`。

> 以下为**已被取代的旧设计**，保留作记录：

- **要消除的结构性风险**：沉底依赖"人记得核对"，且沉底后从主视图消失。
- **形态**：沉底前拦截 → 按 IP 聚合、一次列清 → 要求选择结论（`已核实无影响 / 已上报 / 需处置`）。
- **承重墙是审计留痕，不是弹窗本身**；追责标准是「结论与事实是否相符」，不是「有没有走形式」。
- **打扰对象**：默认只要求监控人员自己填结论；仅当结论为「需上报 / 需处置」时才升级到负责人。
- **分层**：高危卡门禁 / 中危仅提示 / 低危忽略。**分层依据不得单用 WAF severity**（部分 WAF 一律给 `HIGH`），改用「放通规则等级 + 本系统 `priority_score`」。
- **门禁强度自衰减**：同一形态被多次确认为业务 → 降级为"一键确认同上"；出现一次"需处置" → 该形态降级重置。
  —— 实现上**复用「临时规则」这一原语**（个人、有期限、自动过期），不新增机制。
- **两条不可破的底线**：降摩擦 ≠ 豁免（告警仍出现、仍计入统计）；降级必须有期限、可复核。
- **⚠️ 前置依赖**：原始设计以"该 IP 近期存在**高危放通**报文"为触发依据，而**"放通"字段需要 WAF disposition 支持（见 D1，已延后）**。因此需先决定走哪条：
  - **甲**：等 D1（接 WAF 放通字段）——语义准，但要前端/上游先动。
  - **乙**：先用粗代理——"该 IP 近期存在 `priority_score` 超阈值的告警"即触发门禁；不需要任何外部字段，可立刻做。
- **待决**：触发依据（甲 / 乙）、时间窗口（暂 24h）、分层阈值。

## 6. 已落地（0.4.0）

- **优先级模型**：`优先级 = 单次漏洞损失(元) × 目标权重`。损失按「攻击类型 × 等级」查表（护网/众测分级比例推导的**示意默认值**，可由甲方校准）；权重只表系统重要性，范围 **0.5 ~ 3**。成本不再作除数，改为**红线 `red_line`**（默认 30 元）——低于红线**照常入库、照常展示，仅标绿**。
- **评分配置热加载**：改 `financial_factors.yaml` **无需重启**。
- **日报「未分类攻击类型」**：把"出现新攻击类型"变成可见的事；补录配置即自动移出清单。
- **规则版本化（不可变版本）**：修改 = 注销旧版本 + 新建新版本；注销即失效，其隐去的告警自动回到主视图。
- **内网源视图（分区）**：`intent=exempt` 的全局规则定义内网源；命中的告警始终从主视图移出，改由内网源视图承载。**分区不是沉底**——统计口径不分离。
- **统计口径**：`total / action_sunk / rule_sunk / sunk_total / pending / sunk_ratio`，修正原「待处理」被沉底口径污染。
- **按需归因**：详情页 `hidden_by` 实时计算"本条被哪些规则隐去"（查询时算，不落字段）。

## 7. 已知边界（不是待办，是边界声明）

1. **身份是软控制**：系统内用户取自 Cookie，Basic Auth 为单一共享账号。**生产环境应在网关层统一认证**，本系统不承担。
2. **前端依赖公网 CDN**：内网隔离部署需把 Bootstrap 本地化到 `static/vendor/`。
3. **分数不溯以往**：优先级在入库时算定；改配置只影响此后新入库的告警。
4. **降摩擦 ≠ 豁免**：被沉底 / 被划入内网源的告警**仍入统计、仍可检索**（过滤只在读取层）。
5. **损失表变更无审计**：`attack_loss` 是普通配置文件，改它不留"谁改的"记录（资产权重有审计）。
6. **豁免优先**：一条告警若同时命中「内网源豁免」与「沉底规则」，出现在**内网源视图**里。
